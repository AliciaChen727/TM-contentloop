## 2026-08

- **2026-08-22 · Publish results: stale error kept after successful retry, failure history preserved.** After an Instagram retry succeeded, Firestore held both `error: "Fatal"` and the new `postId`. Root cause: `set(patch, {merge: true})` deep-merges nested maps, so a missing key never disappears. Fix: a pure `buildPlatformEntry()` in `lib/content/publishResultEntry.ts` returns the keys to clear, the caller deletes them with `FieldValue.delete()`, and the previous error moves into a new `failures[]` list (max 5). Eight tests added, one reproducing the real 8/17 to 8/22 sequence. Data repair: 3 of 45 drafts were affected and fixed. UI does not yet display `failures`. [`2ae25c6`](https://github.com/AliciaChen727/TM-contentloop/commit/2ae25c6)
- **2026-08-22 · Instagram publish errors keep the full Meta error.** A scheduled 10-image carousel published to Facebook but failed on Instagram, and every record said only "Fatal". Root cause: `publishIg.ts` stored only `error.message`, which for Meta's generic `code -1` carries no information. Fix: `formatMetaError()` keeps `error_user_title`, `error_user_msg`, the original message, `code`, `error_subcode`, `type` and `fbtrace_id`; container polling reads `status` as well as `status_code` and handles error payloads instead of waiting 90 s; carousel errors name the failing slide and file. Seven tests, the first pinning the real 8/17 payload. Success/failure decisions unchanged. [`8e13bd8`](https://github.com/AliciaChen727/TM-contentloop/commit/8e13bd8)
- **2026-08-22 · Phase 5-2c-0 webhook runtime rebuilt (still dry-run).** The Meta webhook handler ran embedding lookup and Claude reply generation before returning 200 (3.5 s locally), risking Meta retries and duplicate inbox writes. Now: verify signature, claim `metaWebhookEvents/{mid}` in a transaction, return 200, and do the work in `waitUntil`. Idempotent state machine (`done` skip, `processing` lease 3 min, `failed` or expired lease re-claim) replaces a boolean flag that would have silently dropped messages on retry. Event records store identifiers only with a 30-day TTL; message bodies go to the page-scoped inbox. `waitUntil` does not throw off-Vercel, so local runs `await` directly via a `process.env.VERCEL` switch. Five scenarios verified. TTL policy must be enabled in the Firestore console. Docs corrected (Vercel route, not Cloud Function) and App Review §10 added: Live mode is not the same as permission availability, and the two messaging scopes were reviewed as read-only, so 5-2c auto-reply needs a new review. [`ae29638`](https://github.com/AliciaChen727/TM-contentloop/commit/ae29638)
- **2026-08-09 · Onboarding moved after authorization; onboarding API authorization fixed; dotted-key cleanup.** New `/auth/onboarding` page is the OAuth callback target; it asks for the missing optimization goal per page using `tokensOnly` (the full list would make super-admins fill in every page). Queue computed once on load to avoid infinite loops for skippers. Security fix: `/api/user/onboarding` GET/POST previously verified identity but not page access, letting any signed-in user read or overwrite another page's onboarding data; now returns 403 via `getUserPageAccess`. Six literal dotted fields cleaned up. Lessons: Firestore `update({'a.b': delete})` treats the dot as a nested path (use `FieldPath`); React 18 StrictMode double-run with a ref guard plus cleanup unsubscribe leaves zero listeners and a page stuck on loading. [`016cd75`](https://github.com/AliciaChen727/TM-contentloop/commit/016cd75)
